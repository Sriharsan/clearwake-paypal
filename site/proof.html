    Built for two people

    One loop, every case

    Item not received, from shipping to two receipts.

    Every part of Clearwake is a step in this one sequence. No step is a separate product.

    1. 0

      Rules, set once, in plain words

      The merchant says the limits out loud. The buyer sets what their agent may claim. After that a model can propose anything, and it can never go past the signed rules.

    2. 1

      Prevention

      When the merchant ships, Clearwake adds the tracking to PayPal through the Add Tracking API, so the order is ready to defend before any dispute exists.

    3. 2

      The buyer's agent watches

      When the tracking stalls past the expected date, it opens the item not received dispute in PayPal, inside its mandate. It can only claim for orders its mandate covers.

    4. 3

      The merchant's agent reads

      The dispute, the order, the tracking on PayPal, and the signed dispatch record, with the photo count where there is one.

    5. 4

      The model drafts, the rules decide

      Delivered with proof: send the evidence. In transit: message the buyer's agent with the tracking and a date. Not shipped, lost or short shipped: offer a refund or a partial settlement inside the merchant's limits, sent alone. The buyer's agent accepts only what its mandate allows.

    6. 5

      Both sides read PayPal's record

      Until it says RESOLVED. A lost response is never retried blindly, and nothing is paid twice.

    7. 6

      Two signed receipts

      One from each side. Both name the same PayPal dispute id, and both verify offline.

    Checking the receipts.

    1. Buyer agent

      A dispute opens.

      The buyer agent (qwen3.5:4b) wrote in PayPal's Resolution Center on dispute PP-R-ISN-10198775: "Order 0HW636872W597254K ($9.00) item not received. Request refund for the affected amount." The merchant's rule: settle an item that has not arrived on its own up to USD 5.00, ask the owner from USD 5.01 up to USD 9.00, never more.

    2. Receipt 1, dispute.decision

      The model proposes, the policy decides.

      qwen3.5:4b proposed settle_by_offer. The policy accepted it: offer USD 5.00, inside the owner's limit of USD 5.00 alone, no approval needed.

    3. Receipt 2, model.call

      The model call is signed too.

      qwen3.5:4b on ollama, 14.6 s, 211 prompt tokens, 17 completion tokens. Overridden: false. Fallback: false. Injection signals: none. The receipt holds the SHA-256 of the prompt and the policy hash.

    4. Receipt 3, dispute.offer_sent

      One offer, sent alone.

      USD 5.00, sent as an offer alone, because PayPal refuses an offer after a seller message.

    5. Receipt 4, dispute.settlement

      PayPal's record is the judge.

      PayPal reads UNDER_REVIEW at INQUIRY. Nothing is counted as settled until PayPal's own record says RESOLVED, so the receipt is signed as pending.

    6. Receipt 5, dispute.settlement

      Resolved, no claim, no dispute fee.

      PayPal reads RESOLVED (RESOLVED_BUYER_FAVOUR) at the INQUIRY stage. Refund USD 5.00, USD 0.77 settlement fee instead of the USD 15.00 dispute fee. The buyer agent signed its own closing receipt on its side.

      Inside and outside

      One gateway out, and only to the PayPal sandbox.

      Inside

      • Dispute text, buyer messages and evidence drafts
      • The policy file, the approvals and the limits
      • The local model and the signed receipts

      Agents have no route out. In case m their DNS lookups fail.

      Outside, through one gateway

      • Only api-m.sandbox.paypal.com is allowed (policy/merchant.yaml)
      • Only what the PayPal call needs: a message, an offer amount, tracking facts
      • Any other host is refused and receipted. In case m, example.com got a 403

      The gateway's 34 receipts from that run are published with the others.

      How to run it

      Python 3.12 or newer. Nothing to install.

      It starts on local records and makes no network calls.

      git clone --recurse-submodules https://github.com/Sriharsan/clearwake-paypal.git
cd clearwake-paypal
python -m clearwake --port 8810

      Then open http://127.0.0.1:8810/console. Speak to it from a phone with python -m clearwake --phone. The network isolated run needs Docker and your own sandbox keys: python scripts/airgap.py. Check a receipt log with the network off: python -m verdock_core verify <log.ndjson> --public-key <64 hex characters>.
